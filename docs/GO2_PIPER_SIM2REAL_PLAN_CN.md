# GO2-PIPER 技能迁移与实机落地推进计划

更新日期：2026-09-15。性质：开发计划，三项技能的训练/复用与原生阶段验收已完成，箱体 MuJoCo 动态迁移仍未通过，尚未实机测试。

起始代码：`324b7a7`，当前分支 `feature/go2-piper-sim2real`。ARX5 既有成果以 [主交接](AGENT_HANDOFF_CN.md) 为准；本组的新目标与优先级以本文和后续用户指令为准。

当前执行状态见 [PIPER 专属交接](GO2_PIPER_HANDOFF_CN.md)：NAV 已复用现有 actor，最终平地目标到达为 98/100；PUSH 原生两组 31/32、30/32，CLIMB 原生两组 30/32、32/32，三份策略包与录像已归档。PUSH/CLIMB 的最终 MuJoCo 结果仍为 21/32、0/32，下一步优先解决动态迁移并准备实机接口。以下阶段规格和资源清单保留计划初稿语境，实际已完成项、失败和复现命令以专属交接为准。

## 1. 目标与小组分工

项目分为两个独立推进的小组：

| 小组 | 主要目标 | 本组协作边界 |
| --- | --- | --- |
| 仿真与世界模型组 | 沿现有 GO2-ARX5 仿真方案推进世界模型 | 保留其默认机器人、策略、训练任务和数据语义；按需交换经过验证的接口改动 |
| GO2-PIPER 实机组，即本组 | 将现有训练与部署方法迁移到实际拥有的 GO2-PIPER，完成技能训练及实机验证 | 独立机器人配置、策略包、实验记录、部署入口和 Git 分支 |

最终交付是 GO2-PIPER 的 NAV、PUSH、CLIMB 技能及真实机器人上的受控闭环验证。先完成平地导航、真实末端推箱和低台登高，再推进移动箱支撑与高台组合。STOP/急停作为控制与终止机制实现；JUMP 不属于本轮任务。

本组可先使用人工给定目标和经过标定的场景定位，完成物理技能落地，不依赖另一组先完成世界模型。需要把实测状态与高层命令接口留给后续融合。

## 3. 迁移原则与加速方法

1. **先复现 PIPER 已有基线。** 若现有 PIPER actor 可用，直接作为 NAV/WBC 起点；如果失败，先定位资产、观测和执行器差异，再决定是否重训。
2. **复用方法，重新核验机器人契约。** 保留 ARX5 的 PPO、课程、失败标签、独立评估、导出 manifest 和 Sim-to-Sim 方法。机器人质量、惯量、安装位姿、关节顺序、默认姿态、PD、延迟、限幅与 IK 均以 PIPER 为准。
3. **新策略独立保存。** 不将 ARX5 权重或 profile 当成 PIPER 已验收策略。只有结构、归一化和特征语义匹配时才试权重初始化，并与 PIPER 自身基线对照。
4. **先小规模冒烟，再扩大训练。** 先检查环境能 reset、观测/动作有限、奖励与失败条件生效，再开启大并行 PPO；不照搬 ARX5 的更新次数作为 PIPER 收敛保证。
5. **硬件约束前置。** 在长训练前确定腿部与机械臂实际控制模式、反馈频率、延迟、速度/力矩限制和可获得观测，避免训练出硬件无法执行的动作。
6. **按技能并行，按门槛串行放行。** PUSH 与 CLIMB 可在共同机器人基线通过后独立训练；硬件通信与日志开发可同步推进。组合执行必须等待各技能及切换契约通过。
7. **随机化覆盖实测误差。** 根据标定与日志确定安装/负载、惯量、摩擦、执行器强度、PD 误差、延迟、传感器噪声及状态估计偏差的范围，先在窄范围收敛，再扩大并用独立扰动集验收。通信失效由硬件故障处理兜底，不依赖策略随机化替代。

ARX5 的 29/32 组合结果仅用于理解方法与历史失败，不作为 PIPER 的验收结果。ARX5 中被接受的前扑式 CLIMB，也需要重新检查 PIPER 的载荷、关节余量和实机落稳表现。

## 4. 分阶段执行计划

### P0：固定实物规格与机器人契约

工作内容：

- 建立硬件清单：GO2 版本及低层接口权限、PIPER 型号/固件/控制模式、安装板、末端/夹爪、线缆、计算机与传感器负载。
- 对齐 Isaac USD、MuJoCo MJCF 与实物：总质量/质心、各 link 惯量、底座安装位置、足端与末端碰撞、关节轴/零位/方向/限位；区分资产给定值与实测值。
- 冻结腿部 12 轴与机械臂 6 轴的命名和顺序。夹爪额外自由度单独记录，不假定属于 actor 的 18 维动作。
- 核验腿部低层控制和 PIPER CAN/SDK 的可用模式。若机械臂仅能稳定运行位置/速度命令，仿真按该接口的延迟、滤波与限幅建模，不以理想力矩执行代替。
- 检查所有模型、策略文件是否完整，记录 hash；确认现有权重是部署 actor 还是包含优化器/critic 的可续训 checkpoint。
- 将控制周期、物理步长、PD/饱和、首命令延迟队列、观测历史、坐标系和单位保存为独立 PIPER profile。

交付与放行：机器人清单、关节/接口映射、资产与控制 manifest，以及模型加载、FK/Jacobian、重力/静态支撑和限幅对照报告。未知硬件参数必须列为待测，不能默认沿用 ARX5。

### P1：恢复 PIPER NAV/WBC 基线

工作内容：

- 复现 `GO2-PIPER-Flat` 与必要的 WBC 能力；先核验已有 actor，缺失可用策略时再训练 PIPER 专属基线。
- 对齐 Isaac 与 MuJoCo 的关节映射、四元数/速度坐标系、动作裁剪、三帧或实际配置的历史顺序、启动稳定和逐物理步延迟。
- 建立可无头运行、可保存逐步日志的 PIPER runtime。机器人与策略由显式配置选择，保留 ARX5 默认行为。
- 验证收臂行走、停止、转向及任务需要的伸臂姿态；不能仅验收空载 GO2 或单一机械臂姿态。

交付与放行：PIPER NAV 策略包、Isaac 原生和 MuJoCo 对照报告、固定种子的录像与失败记录。通过后冻结首个 PIPER locomotion 基线。

### P2：迁移 PUSH 与 CLIMB 独立训练

PUSH 路线：

- 在独立 PIPER 配置中迁移 ARX5 Box-Push-Hybrid 方法，优先尝试腿部 actor 加限速机械臂 IK 的结构；是否保持 226 维输入、12 维 actor 输出，由观测与动作契约核验决定。
- 按 PIPER 运动链重建 IK、末端目标坐标系、可达区域、奇异位形和关节限位处理。核对动作历史是否保存实际下发的完整组合命令。
- 从可稳定接触的箱体高度与低阻工况开始，再进入正常摩擦。先用受控仿真工况对照 ARX5 的 5 kg、摩擦 0.4、20 cm 箱与 60 cm 推移目标；若 PIPER 末端几何不适配，先记录原因再调整任务。
- 保留接近、接触、推进、有向停车、验证与退出阶段；成功必须包含指定末端真实接触，机身或腿部代推记失败。
- 独立统计目标误差、侧偏、异常接触、饱和与超时，防止策略用绕过接触规则的动作获得成功标签。

CLIMB 路线：

- 复用高度课程、近地面初态、低姿态失败、静止零收益与落稳判据，训练 PIPER 专属候选。
- 先固定低台，逐步提高到实物与机构允许的箱高；20 cm 是对照目标，不能预先声明 PIPER 或实物具备该能力。
- 固定支撑通过后进入自由移动箱；第二段高台另设候选与独立原生评估，避免将组合成绩当作单 actor 成绩。
- 使用真实上一技能结束状态建立起步数据池，训练/评估按来源 episode 与 seed 分离；数据中的 reset 仅用于独立训练或离线分支。
- 记录机械臂姿态、机身接触、足端支撑、落稳窗口和载荷变化；是否需要更保守动作由实机执行约束决定。

交付与放行：分别保存 PUSH、登箱、必要时高台三个候选包与原生报告。新任务名称建议使用 `GO2-PIPER-Box-Push-Hybrid`、`GO2-PIPER-Box-Climb`，均为待新增名称，当前不能直接作为已注册任务运行。

### P3：Sim-to-Sim 与连续技能闭环

工作内容：

- 将 PIPER 候选接入 MuJoCo，先做同状态的观测、推理、FK/Jacobian、重力与首步目标对照，再运行物理回合。
- 优先核对 ARX5 中已出现过的偏差：质量/安装、接触力坐标与含义、零目标延迟队列、root 速度、腿部速度限制和机械臂增益。
- 顺序验证 NAV-PUSH-NAV、NAV-CLIMB-NAV，再验证推箱、箱面对位、登箱、顶面定位与第二段登高。
- 真实技能切换不 reset 物理 episode，不改写箱体位置、摩擦或固定状态来制造成功；仅允许按契约切换控制器内部状态。
- 跨机器复现沿用 [显式 CPU 启动方式](../mujoco/run_box_support_sequence.py) 的数值固定思路；PIPER 入口另行适配，报告绑定后端与线程配置。
- 接入现有 executor、快照与事件记录，补齐中断、拒绝、超时和失败原因。对触及的 ARX5 公共行为运行已有聚焦回归。

交付与放行：PIPER 单技能及连续流程的冻结评估集、报告、录像、manifest 和失败清单。扩大工况时分别报告质量、摩擦、尺寸、间隙、安装/载荷及起点的边界结果。

### P4：实机接口与观测闭环

此阶段的只读通信、标定和离线回放可与 P1-P3 并行；电机动作按对应技能的仿真与控制门槛逐级放行。

工作内容：

- 基于实物支持的 Unitree/PIPER SDK 建立腿部与机械臂硬件适配器，确认通信权限、CAN/网络接口、时间戳、控制所有权和指令确认机制。
- 统一策略周期与不同执行器刷新频率；检测状态过期、丢包、乱序、超时和两个控制器的时间偏差，禁止使用陈旧反馈持续出动作。
- 建立启动、自检、使能、姿态过渡、运行、停止、故障与人工急停状态机。明确每类故障采用受控保持还是禁能，并在受保护条件下验证。
- 独立夹爪管理、关节/速度/力矩或电流限制、动作变化率限制，记录每次限幅和故障；不能用全部关节零目标作为通用安全停止。
- 保存实测关节/IMU、策略输入、原始动作、限幅后实际命令、通信延迟、温度/电流及模式切换，支持离线逐步重放。

必须逐项落地的观测来源：

| 仿真/控制信息 | 实机候选来源 | 放行要求 |
| --- | --- | --- |
| 关节状态、机身角速度、重力方向 | 编码器、IMU、SDK 状态 | 单位、零位、坐标系、时间戳与训练一致 |
| 基座线速度与位姿 | 接触/惯性状态估计、里程计或经标定的外部定位 | 明确误差、延迟及失效处理，不能假定有仿真真值 |
| 高度扫描、箱体和平台几何 | 实物可用雷达/深度相机，或首版受控试验的外部测量 | 按 actor 真正读取的字段逐项闭合；缺失时先补感知或调整并重训观测 |
| 足端/末端接触与推力 | 可用传感器、经验证的电流/力矩估计或外部测量 | 区分实测和估计；未经标定的电流不能直接等同接触力 |
| 速度命令、推移/登高目标 | 操作员或上层任务接口 | 命令有效期、可达范围与停止语义明确 |

首版允许外部定位或人工测量已知场景，但报告必须说明这些依赖；闭环执行不能读取实物上不存在的仿真状态。世界模型不是技能实机验收的前置条件。

交付与放行：实机通信/日志工具、标定文件、逐字段观测映射、离线回放一致性，以及超时、断连和急停测试记录。

### P5：实机分级验证与组合演示

按以下顺序推进，每一级先检查日志与实物行为，再扩大动作范围：

1. 只读状态与离线推理，确认映射、频率和输出范围。
2. 受保护条件下分别测试机械臂与腿部的低幅动作，验证使能、限幅、停止和急停；保护方式按硬件选择，避免悬空状态误触发正常行走策略。
3. 平地站立、低速 NAV、转向与停止，覆盖收臂及任务所需姿态。
4. 轻载低阻真实末端 PUSH，逐步增加到已验证的正常摩擦工况。
5. 固定低台 CLIMB，再进入经过支撑稳定验证的移动箱；确认安装板、线缆和末端无干涉。
6. 单技能与切换通过后开展组合；第二段高台必须具备单独的放行证据。

场地准备包括独立急停、保护/支撑装置、操作员、隔离区域及可测质量/几何的箱体和台阶。首次失败保留日志并定位，先在仿真或离线回放验证修正；不以连续上机重试代替排错。

实机日志用于系统辨识：比较实际命令与关节/机身响应，修正执行器延迟、饱和、负载或接触参数；必要时再训练或微调 PIPER 候选。每轮修正更新 profile 和数据来源，经冻结仿真回归及独立实机验证后放行，标定数据与最终验收数据分开。

交付：每个技能和组合的实机视频、日志、场景参数、策略/profile hash、成功与失败统计，以及当前允许使用的硬件和场景范围。

## 5. 评估标准与数据隔离

下表为建议的阶段门槛，P0 根据实物和任务范围冻结后执行；它们不是已取得的成绩。不得在查看测试失败后删 seed、放宽判据或挑选最佳录像替代统计。

| 层级 | 建议检查 | 放行依据 |
| --- | --- | --- |
| 契约/模型 | 映射、FK/Jacobian、动力学、观测、启动/延迟、限幅、导出推理对照 | 全部关键项通过；容差在运行前记录 |
| PIPER NAV | 独立 100 个仿真回合，包含朝向和机械臂姿态变化 | 成功率至少 95%，无跌倒及非法接触 |
| PIPER PUSH/CLIMB 单技能 | Isaac 和 MuJoCo 分别使用两个独立的 32 回合评估组 | 每组至少 30/32；接触违规、失稳、超时均计失败并定位，异常接触失败未解决时不放行该实机工况 |
| PIPER 连续流程 | 冻结 32 个组合回合，另列边界集 | 建议至少 30/32；物理 reset 仅初始化一次，各阶段结果单列；剩余失败工况不直接上实机 |
| 硬件通信/故障 | 状态过期、命令超时、断连、模式冲突及人工急停 | 每项按预定动作处理，日志可回放，不能由策略网络承担安全控制 |
| 实机单技能 | 每个固定工况先完成连续 10 次受控验证，再增加范围 | 无跌倒、非法接触或失控；任何故障中止该级放行并保留失败记录 |
| 实机组合 | 单技能和切换通过后，在冻结场景做重复测试 | 报告全部尝试、阶段成功率、人工干预与传感器依赖；不据此外推任意布局 |

训练 seed、调参集、原生测试、MuJoCo 测试与实机验证分开管理；起步状态及其派生候选按来源 episode 分组，避免泄漏。新增实机数据使用独立机器人/场景标识与 schema 版本，不混入 ARX5 世界模型数据而不做说明。
